# SafeMotion 三方案筛选过程记录

> 这是我从「拿到题目」到「最终选定 kimi 版」的完整决策过程。
> 目标：让面试官看到我不是随便交一份代码，而是用可复现的方法筛选出了最优方案。

---

## 1. 先读懂题目的「验收红线」

拿到题目的第一件事，不是写代码，而是先读它的「原则上不通过」条款。这道题（VLA 机械臂安全执行器）真正要考的不是深度学习，而是**纯软件安全过滤的工程能力**，有 6 条红线：

- 项目无法按 README 运行 → 不通过
- 只查 TCP 不查连杆 → 不通过
- 安全过滤失败后还执行原动作 → 不通过（必须输出零速度）
- 最终执行轨迹越出 workspace → 不通过
- 测试针对固定坐标写死 → 不通过（会用隐藏轨迹验收）
- 候选人无法解释核心安全逻辑 → 不通过

**这决定了我的筛选标准**：安全性 > 算法精度 > 完整度，且「隐藏场景下的健壮性」比「demo 好看」更重要。

---

## 2. 策略：三个 agent 并行，独立实现

题目明确允许 AI 编程工具辅助。我没有让一个 agent 反复改，而是让 **codex / deepseek / kimi** 三个 agent **各自独立**实现一份完整方案。

这样做的目的：
- 三个独立实现 = 三个不同的设计视角，能互相印证、互相暴露盲区；
- 我可以做**客观的横向对比**，而不是在单一实现里自说自话。

三份方案各有侧重（第一版）：

| | codex | deepseek | kimi |
|---|---|---|---|
| 完整度 | 最高（7 测试 + 5 场景 + README） | 中等 | 缺测试/文档 |
| 几何检查 | 凸集性质（精确） | 连杆采样 | 凸集 + 采样兜底 |
| 安全过滤 | 固定档位缩放 | 固定档位 | 二分细化 + 子步 |
| 关节越界 | 拒绝 | 钳位 | 拒绝 |

---

## 3. 测试方法论：公平、可复现、防作弊

这是整个筛选过程最核心的部分。我以「独立测试人员」的视角，设计了一套黑盒测试框架：

1. **同一批随机数据**：固定随机种子，生成 100 组轨迹（88 组随机游走覆盖「安全→轻微越界→明显越界」+ 8 组非法输入 + 4 组关节越界）。
2. **种子保密**：seed 由测试方私下传入，不写死在脚本里——防止 agent 看到数据后「针对坐标写死」（这本身就是题目的红线之一）。
3. **统一指标**：
   - 偏差：`joint_dev`（关节空间）、`tcp_dev`（TCP 笛卡尔空间）、`final_gap`；
   - 安全不变量：是否越界、是否破关节限位、是否输出非有限速度、是否崩溃。
4. **三版跑同一批数据**，指标口径完全一致，结果可直接横向对比。

```
固定 seed → 100 组随机轨迹 → run_scenario → {偏差 + 安全不变量} → CSV/JSON
```

## 4. 第一轮测试：发现一个真 bug + 三个设计分歧

### 发现的 bug：deepseek 在 `action_hz=0` 时崩溃

deepseek 的 `replay.py` 把 `dt = 1.0 / action_hz` 写在了**输入检查之前**。当 `action_hz=0` 时直接 `ZeroDivisionError` 崩溃，而不是被拒绝。

**根因**：输入检查（含 `action_hz>0`）没有放在所有计算之前兜底。codex 和 kimi 都把校验放在最前面，所以正确拒绝。

这正好踩中红线「非法输入不得进入 Mock Robot」——崩溃 ≠ 拒绝。

### 三个设计分歧（面试时要能讲清楚）

1. **关节目标越界**：codex/kimi 选「拒绝」（符合第 3 节字面），deepseek 选「钳位」（第 7 节最小修改）——语义相反。
2. **几何检查**：codex 用凸集性质（凸盒内端点在内 ⟹ 整段在内，精确）；deepseek 纯采样（需说明误差）；kimi 凸集 + 采样兜底。
3. **安全过滤精度**：kimi 有二分细化，codex/deepseek 只有固定档位。

第一轮结论：**codex 完整度最高、kimi 算法最精、deepseek 有硬伤**。

---

## 5. 迭代：让 codex 补二分、让 kimi 补完整度 + QP

第一轮暴露的问题，我反馈给对应的方向：
- **codex** 补上了**二分细化** + 审计记录（`attempts`）+ `nominal_margin` 指标；
- **kimi** 补上了 **README/pyproject/测试/场景**（补齐完整度），并加了 **QP 方法**（题目第 7 节「优化方法」加分项，SLSQP 二次规划）。

---

## 6. 第二轮测试：kimi 反超

用新的秘密 seed 重新测，四组结果：

| 指标 | codex(二分) | deepseek | kimi scaling | **kimi QP** |
|---|---:|---:|---:|---:|
| crash | 0 | **1** ❌ | 0 | 0 |
| mean_joint_dev | 0.0285 | 0.0646 | 0.0188 | **0.0103** |
| mean_stopped | 2.61 | 2.83 | 2.68 | **0.0** |

- codex 加二分后偏差减半（0.057 → 0.0285），0 crash；
- deepseek 的 bug 没修；
- **kimi QP 是最优**：`mean_joint_dev=0.0103`（最低）、`mean_stopped=0`（贴边时沿边界滑行，而不是撞墙停下）。

QP 的「滑行」正是方法 B 的核心优势——它把「朝边界的法向推压」转成「切向运动」，实现真正的**最小修改**。

---

## 7. 最终决策：选 kimi 版

综合排序：

| 维度 | 排序 |
|---|---|
| 算法精度 | kimi QP > kimi scaling > codex > deepseek |
| 完整度 | codex ≈ kimi > deepseek |
| 可靠性（无 crash） | codex = kimi > deepseek |

**结论：kimi 版** —— 补齐完整度后，它是「scaling + QP 双方法 + 二分细化 + 三层防线 + 6 测试 + 8 场景 + README」的最全形态，且算法精度最高、0 crash、0 违规。

## 8. 这个过程体现了什么

1. **快速学习**：一天内从「拿到一道具身智能题」到「理解其本质是运动学 + 几何 + fail-safe 的纯软件问题」。
2. **产品理解**：先读验收红线，再定筛选标准，避免「demo 好看但不安全」。
3. **工程判断**：能定位 bug 根因（`dt` 计算顺序）、能评估设计权衡（拒绝 vs 钳位、凸集 vs 采样、缩放 vs QP）。
4. **落地能力**：用可复现的测试框架，把「三选一」从一个主观判断变成一个有数据支撑的结论。
